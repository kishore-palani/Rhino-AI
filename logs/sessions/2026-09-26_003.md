## 5. Key Findings

### 5.1 Rhino MCP Architecture

**Transport:** stdio (not HTTP/TCP)
- Router: `rhino-mcp-router.exe`
- Location: `%APPDATA%\McNeel\Rhinoceros\packages\8.0\Rhino-MCP-Platform\0.1.5\router\win-x64\`
- Protocol: JSON-RPC 2.0 over stdio

**Slot system:**
- Rhino instances are spawned as "slots" (named: aardvark, badger, axolotl, etc.)
- Each slot gets a unique HTTP endpoint (e.g., `http://localhost:10500`)
- Slots run independently and can be closed/reopened
- Default slot auto-spawns if none exists

**Available tools (29 total):**
- **Scripting:** `run_python`, `run_csharp`, `run_command`
- **Queries:** `list_objects`, `get_selection`, `get_viewport_image`, `get_commands`
- **Slots:** `spawn_slot`, `close_slot`, `list_slots`
- **Grasshopper (g1_*):** Components, connections, solving
- **Document:** `open_doc`, `close_doc`, `save_doc`
- **Viewport:** `set_camera`, `zoom_to_object`, `zoom_to_layer`

### 5.2 Script Execution Model

**Python (`run_python`):**
- Injected variable: `__rhino_doc__`
- Do NOT trust `scriptcontext.doc` or `rhinoscriptsyntax` defaults
- Returns JSON: `{"stdout": "...", "error": null}`

**C# (`run_csharp`):**
- Injected variable: `__rhino_doc__` (type `RhinoDoc`)
- Do NOT use `RhinoDoc.ActiveDoc`
- Full RhinoCommon API access
- Returns JSON: `{"stdout": "...", "error": null}`

**Commands (`run_command`):**
- Direct Rhino command string execution
- Example: `"_Box 0,0,0 10,10,10"`
- Returns: `{"payload": "Done."}`

### 5.3 Integration Points

**For AI-RHINO-ARCHITECT project:**
1. Use `run_csharp` for complex geometry (faster, more reliable)
2. Use `run_python` for rhinoscriptsyntax-style operations
3. Use `run_command` for simple built-in Rhino commands
4. Always pass `"slot"` parameter to target specific Rhino instances
5. Parse JSON responses: `{"stdout": "...", "error": "..."}` or `{"payload": "..."}`
