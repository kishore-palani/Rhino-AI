## 4. Next Phase Recommendation: **Phase 5 Completion + Phase 6 Foundation**

### 4.1 Why This Sequence?

1. **Phase 5 Memory is 60% complete** — AgentMemory integration exists but lacks:
   - Skill execution memory (what worked, what failed, under what conditions)
   - Failure pattern recognition (learning from repeated errors)
   - Feedback analysis system (structured user correction storage)

2. **Phase 6 Architecture Knowledge is the logical next major capability** because:
   - The planner (Phase 3) can generate plans but lacks architectural reasoning
   - The validator (Phase 4) checks rules but doesn't understand spatial relationships
   - The skills (Phase 2) execute geometry but don't know functional requirements
   - Knowledge base bridges "raw geometry execution" to "architecturally intelligent design"

3. **Current Foundation is Solid:**
   - 100 passing tests, 83% coverage
   - Clean separation of concerns (planner, skills, validators)
   - Proven MCP integration pattern
   - Memory infrastructure ready to expand

### 4.2 Proposed Work: Phase 5 Completion

**Objective:** Complete the memory system to enable experience-based learning

**Deliverables:**
1. **Skill Memory Module** (`ai/memory/skill_memory.py`)
   - Record skill execution attempts with context
   - Track success/failure patterns per skill
   - Store parameter ranges that work vs. fail
   - Enable skill executor to query "has this failed before?"

2. **Failure Pattern Recognition** (`ai/memory/failure_patterns.py`)
   - Aggregate failures by type (geometry, dimension, regulatory, MCP)
   - Detect recurring patterns (e.g., "wall thickness <150mm always fails validation")
   - Provide pattern-based suggestions to planner

3. **Feedback Analysis** (`ai/memory/feedback_analysis.py`)
   - Structure user corrections (dimensional, stylistic, functional)
   - Link feedback to plan steps that caused the issue
   - Enable planner to query "what corrections were made to similar designs?"

4. **Memory Query Interface** (`ai/memory/query.py`)
   - Unified query API for planner and executor
   - Semantic search integration (when pgvector added in Phase 6)
   - Relevance ranking for retrieved experiences

5. **Tests:**
   - Unit tests for each memory module
   - Integration test: full cycle (plan → execute → fail → record → query → retry with memory)

**Estimated Scope:** 4-5 new modules, ~800-1000 lines, 15-20 new tests

### 4.3 Proposed Work: Phase 6 Foundation

**Objective:** Start building architectural knowledge representation

**Deliverables:**
1. **Spatial Relationships Model** (`knowledge/spatial/relationships.py`)
   - Define relationship types: adjacent, contains, connects_to, above, below
   - Room adjacency logic (bedroom should not open to public entrance)
   - Circulation path representation

2. **Building Component Ontology** (`knowledge/components/ontology.py`)
   - Component hierarchy (Space → Room → Bedroom → MasterBedroom)
   - Functional requirements per component type
   - Typical dimensional ranges (not just validation min/max)

3. **Spatial Reasoning Rules** (`ai/reasoning/spatial.py`)
   - Privacy rules (private vs. public space separation)
   - Circulation requirements (rooms need access paths)
   - Orientation preferences (living spaces toward views)
   - Basic layout logic

4. **Knowledge-Enhanced Planner** (`ai/planner/knowledge_planner.py`)
   - Extend base planner with spatial reasoning queries
   - Check proposed layouts against functional requirements
   - Suggest component placement based on relationships

5. **Initial Knowledge Base Files:**
   - `knowledge/components/rooms.json` — Room types and requirements
   - `knowledge/spatial/adjacency_rules.json` — Which spaces should/shouldn't be adjacent
   - `knowledge/dimensions/typical_ranges.json` — Typical (not minimum) dimensions per building type

**Estimated Scope:** 5-6 new modules, 3 JSON knowledge files, ~1000-1200 lines, 12-15 new tests
