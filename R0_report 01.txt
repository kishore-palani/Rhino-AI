# AI ARCHITECTURAL DESIGN AGENT FOR RHINO & GRASSHOPPER

## Project Summary & Development Vision

### 1. Executive Summary

The project aims to develop an **AI-powered architectural design and computational modeling agent integrated with Rhino and Grasshopper**.

The system will go beyond conventional text-to-3D generation.

The objective is to create an AI that can:

* Understand natural-language architectural requirements.
* Understand architectural space and planning.
* Reason about building form and spatial relationships.
* Understand construction methods and building components.
* Understand dimensions, standards, rules and regulations.
* Learn Rhino and Grasshopper modeling workflows.
* Learn from architectural drawings, 3D models, images, sketches and videos.
* Understand how architects and computational designers develop a model over time.
* Generate accurate Rhino geometry rather than only visually plausible meshes.
* Create and modify Grasshopper parametric definitions.
* Experiment with alternative design strategies.
* Validate geometry and design constraints.
* Learn from failures.
* Learn from user feedback.
* Discover new architectural design trends and computational techniques.
* Continuously expand its knowledge without being locked into a fixed architectural style.

The central philosophy is:

> **The AI should not merely memorize architecture. It should learn how architectural decisions are made, how those decisions become geometry, how geometry is constructed, how designs fail, and how designers improve them.**

Rhino and Grasshopper become the AI's **precise design and experimentation environment**.

# 5. Why Video Is Important

One of the most important additions to the project is **learning from video**.

A conventional CAD dataset tells the AI:

> This is the final model.

A video can tell the AI:

> This is how the designer arrived at the model.

That difference is critical.

A video can contain:

```text
Architect's explanation
        +
Visual design changes
        +
Rhino commands
        +
Grasshopper operations
        +
Parameter changes
        +
Design decisions
        +
Failures
        +
Corrections
```

The AI should therefore learn from the **process**, not just the final result.

# 8. Architectural Knowledge Hierarchy

A critical principle is that the AI must distinguish between different kinds of knowledge.

```text
PHYSICAL REALITY
      ↓
BUILDING REGULATION
      ↓
ENGINEERING CONSTRAINT
      ↓
CONSTRUCTION KNOWLEDGE
      ↓
ARCHITECTURAL PRINCIPLE
      ↓
DESIGN PRECEDENT
      ↓
CURRENT TREND
      ↓
EXPERIMENTAL IDEA
```

These should not be treated as equivalent.

For example:

> "A corridor must satisfy a particular minimum dimension under a particular code."

is different from:

> "Architects commonly use this corridor proportion."

which is different from:

> "This proportion is currently fashionable."

The AI needs to understand the difference.

# 16. AI Exploration vs Execution

One of the most important project principles is:

> **Do not restrict the AI's thinking simply because the execution environment needs constraints.**

Therefore the system should have two modes.

## EXPLORE

The AI can:

* Experiment
* Combine strategies
* Generate unconventional forms
* Try alternatives
* Study new architecture
* Test hypotheses
* Make mistakes

## EXECUTE

The final design must:

* Have valid geometry
* Satisfy explicit constraints
* Respect selected regulations
* Respect fabrication limitations
* Pass validation
* Remain editable

Conceptually:

```text
CREATIVE EXPLORATION
        ↓
DESIGN PROPOSALS
        ↓
VALIDATION
        ↓
EXECUTABLE DESIGN
```

This preserves creativity without sacrificing technical reliability.

# 17. Failure Learning

The system should maintain a dedicated **Failure Memory**.

Example:

```text
TASK
 ↓
PLAN
 ↓
EXECUTION
 ↓
FAILURE
 ↓
DIAGNOSIS
 ↓
CORRECTION
 ↓
SUCCESS
```

A failure may be:

### Geometry failure

* Invalid Brep
* Self-intersection
* Open solid
* Boolean failure

### Programming failure

* Invalid RhinoCommon call
* Grasshopper error
* Wrong parameter
* Script error

### Design failure

* Poor proportion
* Poor circulation
* Too heavy
* Too complex
* Poor spatial relationship

### Construction failure

* Impossible joint
* Excessive tolerance
* Fabrication problem
* Assembly problem

### Regulation failure

* Dimension violation
* Accessibility issue
* Fire requirement issue

The AI should learn the **reason for the failure**, not simply memorize that the original solution failed.

    ↓

# 37. Fundamental Design Principles

The project should follow these principles.

### 1. AI should reason, not merely retrieve.

### 2. Geometry should be deterministic whenever possible.

### 3. Architecture should be represented as relationships, not only objects.

### 4. Video should teach process, not merely appearance.

### 5. Regulations should be contextual and source-backed.

### 6. Design conventions should not be confused with regulations.

### 7. The AI should be allowed to explore.

### 8. Exploration and execution should have different levels of constraints.

### 9. Failures should become learning data.

### 10. User feedback should become structured experience.

### 11. New architectural trends should be treated as emerging knowledge, not absolute truth.

### 12. The AI should learn principles rather than copy individual buildings.

### 13. The system should remain multimodal.

### 14. The system should remain model-agnostic where possible.

### 15. The project should avoid training a foundation model from scratch unless later evidence justifies it.

# 38. Most Important Technical Insight

The biggest conceptual shift in this project is:

> **We are not trying to teach an LLM how to draw a building.**

We are trying to teach an AI system:

```text
"What is the designer trying to achieve?"
                    ↓
"What spatial arrangement achieves it?"
                    ↓
"What architectural strategy can achieve it?"
                    ↓
"What geometry represents that strategy?"
                    ↓
"What parametric relationships should exist?"
                    ↓
"Can the geometry be constructed?"
                    ↓
"Does it satisfy the applicable constraints?"
                    ↓
"Did the user like it?"
                    ↓
"What did I learn from the result?"
```

That is the core intelligence we are trying to develop.
